# Remaining desktop CI failures

The [run on c53dec0](https://github.com/johndavidearley/Agentic-NLE/actions/runs/37307428758)
passed Windows desktop and the four-platform MCP-media matrix, but failed Linux desktop linking,
Apple Silicon MCP export cancellation, and Intel macOS sequence supervision.

## Linux runtime linkage

The prepared FFmpeg stub libraries were found after the previous correction. Their own
dependencies, including `libQt6Multimedia.so.6`, were not found by the standalone exporter link.
Linux's optional `nle_decode` now links the matching `Qt6::Multimedia` SDK target so its dependency
libraries and runtime paths accompany decode/export executables. The existing Qt dependency and
license policy apply; no unresolved-symbol suppression is used. The core and lightweight MCP
remain independent of linked Qt/FFmpeg. A real Linux build remains to be confirmed in CI.

## Cancellation during source-open

Apple Silicon's cancelled export returned `Open source: Immediate exit requested` and was
incorrectly classified as failed. The decoder now translates FFmpeg's `AVERROR_EXIT` through
its cancellation/deadline check for open, stream inspection, read and seek. Typed decoder
cancellation propagates through the export engine as typed export cancellation. MCP catches that
type instead of matching error text. Other errors remain failures even if cancellation was
requested; a successfully installed result still wins a late cancellation race. Staging cleanup
continues through normal exception unwinding.

Regression coverage includes a pre-cancelled decoder open, typed cancelled jobs, and an ordinary
error carrying identical cancellation text that must remain failed after a cancellation request.

## Supervision and device-end timing

The Intel macOS log only identified an unlabeled `Wait timed out`; it did not identify the exact
stage or device state. Inspection found a terminal-state gap: a drained audio sink can stop its
integral-microsecond processed clock just short of the final sample. If all PCM has been submitted
and the sink is idle, the worker now recognizes completion rather than waiting for a clock that
can no longer advance. Deterministic checks reproduce the rounded terminal clock and ensure an
active sink, startup-idle device, or incompletely submitted PCM cannot complete early, including
a nonzero seek origin. Completion requires that the device clock has advanced at least once.
Supervision timeouts now report their call-site line. No timeout or performance threshold was
extended. This addresses the identified gap; the original macOS timeout needs a rerun to confirm
whether this was its cause.

Local checks and remote validation results are recorded separately; these changes do not imply
that the failed hosted jobs have passed.

## Local checks

The Windows Release warnings-as-errors build passed. MCP session, official MCP export, and
sequence supervision each passed five consecutive runs (plus repeated corpus setup). The full
Release suite then passed 53/53 in 55.10 seconds with two workers. clang-format 19.1.1 and
`git diff --check` passed. After the final startup-idle guard, the worker and supervision test
rebuilt with warnings as errors and supervision passed three more consecutive runs.
Linux's real link/runtime and both hosted macOS failures remain unverified until CI reruns.
